## 正文草稿

做这个项目的起点很朴素：记账软件不少，但很少回答「下个月这笔钱够不够」「这个月买这个东西会不会把安全垫击穿」「离目标还差几个月」这类问题。

所以我做了 **MoneyFlow 钱流**——一个本地优先的现金流与消费决策工具。数据只保存在浏览器 IndexedDB 里，不登录、不上传。

它现在能做什么：

- **记账**：支出/收入/转账，金额全程整数分；支持一句话快速记账（如「昨天买咖啡18.5元」）。
- **固定计划**：房租、订阅、工资等周期规则，核销后生成真实流水，逾期有独立处理。
- **现金流预测**：30/60/90 天逐日预测，固定收支 + 学习到的可变消费（6 周同星期中位数 → 月预算日均 → 覆盖日日均 → 明确「未估计」）。
- **消费决策沙盘**：对比「不买 / 立即买 / 延期买 / 分阶段预留后买」四条路径的最低余额和风险，并搜索最早安全购买日。
- **储蓄目标**：预留、释放、消费三种事件；三种分配策略；24 个月完成推演。
- **洞察**：周期支出候选、异常消费（中位数/MAD/IQR）、小额高频。
- **校准与回测**：用历史快照与实际流水学习星期偏差；滚动回测无未来泄漏，输出 MAE/RMSE。
- **备份**：完整 JSON 备份带结构校验；CSV 仅导出并防公式注入。

几个实现上的取舍：

1. 预测只有一条引擎，总览、目标推演、沙盘都复用它，避免多套口径互相打架。
2. 「预留」是资金标记（earmark），账户余额不变但可支配减少；只有消费才真正出账。
3. 预测里缺口不补零：样本不足时显示「未估计」，而不是假装当天不花钱。
4. 示例数据由固定种子生成，和真实账本分离，随时可重建。

技术栈：React + TypeScript + Vite + Tailwind + ECharts + Dexie + Zustand，Vitest 97 个测试 + Playwright 10 个端到端用例。

目前仍是个人项目，没有云同步，也没有多币种、信用卡账单、分期和 CSV 导入；这些都在已知限制里写清楚了。

如果大家有兴趣，我可以再写一篇讲预测与校准的具体算法，以及为什么目标分配要用带封顶的注水式分配。
